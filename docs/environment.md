# Build and qualification environment

Development version: 0.1.0. The qualified execution environment is:

| Component | Baseline |
| --- | --- |
| OS | Ubuntu 24.04, Linux x64 |
| SDK / runtime | .NET SDK 10.0.403 / runtime 10.0.14 |
| Server and independent client | slapd / ldap-utils 2.6.10+dfsg-0ubuntu0.24.04.1 |
| Native toolchain | GCC 13.3, glibc 2.39 |
| LDAP NuGet package | Novell.Directory.Ldap.NETStandard 4.0.0 |
| Package source revision | e0cd8d459b759dc9d2d74471d3458e61059d7911 |
| Known logging dependency for that package | Microsoft.Extensions.Logging.Abstractions 9.0.2 |
| Test packages | Microsoft.NET.Test.Sdk 18.0.0; xunit.v3.mtp-v2 3.2.2 |

The regression suite uses actual unprivileged OpenLDAP and the maintained client in this environment. CI prints actual SDK and distribution package versions during dependency preparation. Apt repositories can resolve newer security builds; the Dockerfile does not claim bit-for-bit apt reproducibility. The input SDK image and genuine NuGet lock files should be retained with any independently collected qualification results.

Dependency resolution is intentionally separate from offline validation. The committed NuGet locks were generated by actual package resolution. `dotnet restore MembershipEvidence.sln --locked-mode` consumes those versions and integrity hashes; intentional dependency updates require regenerated, reviewed locks. Ignored `build/` paths are set in Directory.Build.props, not individual projects.

The C helper is compiled during the ordinary build by `cc`, copied to library/CLI/test outputs, and made executable by build targets. A locally built library package includes the compiled Linux helper, original C source, MIT license and a buildTransitive executable-bit target. Package consumption does not invoke a compiler at runtime. This package layout is Linux-specific; no cross-platform native binary claim is made.

The Dockerfile uses policy-rc.d exit 101 and slapd/no_configuration=true before installing packages. It restores/builds during preparation, then changes to UID 1000. CI runs tests/demo with all capabilities dropped, no-new-privileges, no external network, 1 GiB memory and two CPUs. This is a test configuration, not a deployment workflow.

Useful local inspection commands after preparation:

```sh
dotnet --info
dpkg-query -W slapd ldap-utils gcc libc6
dotnet list src/MembershipEvidence/MembershipEvidence.csproj package --include-transitive
dotnet test --solution MembershipEvidence.sln --no-restore --configuration Release
```

Qualification covers the declared synthetic scenarios and toolchain. It does not establish behavior on arbitrary remote directories or other native platforms.
