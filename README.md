# LDAP Membership Evidence Lab

**Development version 0.1.0.** Original MIT software by [Lofrano Tecnologia](https://lofranotecnologia.com.br).

Observe nested synthetic service groups through an owned OpenLDAP server. Explain shortest membership paths, duplicate routes, cyclic components, missing references and resource exhaustion. This is not authentication, authorization, or an access-granting service. No external directory endpoint or credentials can be configured.

## Install and prepare

Supported build/runtime target: Linux x64, Ubuntu 24.04, .NET SDK 10.0.403, OpenLDAP 2.6, and the system `slapd`, `slapadd`, `ldapmodify`, `ldapsearch` tools. A C compiler is required **at build time**, never at runtime. NuGet dependencies are Novell.Directory.Ldap.NETStandard 4.0.0 and development-only test packages. No model/API service is used.

The Dockerfile installs server/client dependencies without starting a system directory. It restores dependencies and compiles the original native ownership helper. Dependency preparation needs network access; the test and demo phases do not:

```sh
docker build --tag ldap-membership-local .
docker run --rm --network none --cap-drop ALL --security-opt no-new-privileges --pids-limit 256 --memory 1g --cpus 2 --user 1000:1000 ldap-membership-local dotnet test --solution MembershipEvidence.sln --no-restore --configuration Release
docker run --rm --network none --cap-drop ALL --security-opt no-new-privileges --pids-limit 256 --memory 1g --cpus 2 --user 1000:1000 ldap-membership-local dotnet run --no-restore --project src/MembershipEvidence.Cli -- demo --assert
```

For an already prepared unprivileged development environment:

```sh
dotnet restore MembershipEvidence.sln --locked-mode
dotnet build MembershipEvidence.sln --no-restore --configuration Release
dotnet test --solution MembershipEvidence.sln --no-restore --configuration Release
dotnet run --no-restore --project src/MembershipEvidence.Cli -- demo --assert
dotnet run --no-restore --project src/MembershipEvidence.Cli -- demo --assert --json
```

Committed `packages.lock.json` files were generated by real NuGet resolution. Use locked restore for normal builds; regenerate and review the locks only for an intentional dependency update. The SDK uses native Microsoft.Testing.Platform, not a VSTest test adapter. Tests require UID other than zero and loopback networking; Docker's `--network none` retains loopback.

## Example output

The human-readable portion is:

```text
LDAP Membership Evidence Lab — development 0.1.0
Original: A, B, C; 3 groups; 6 edges. B: root → G1 → B (2 shortest paths).
Cycle: {G2, root}. Missing member: incomplete, no export.
Replacement: A, B, D; +1 / -1. Group cap: incomplete, no export.
ldapsearch: 3 groups, 6 total links, 4 below G1/G2. Stable exports: 2.
JSON:
```

A JSON report follows. `--json` emits only that report. Its fields include `principals: ["A", "B", "C"]`, `bPath: ["root", "G1", "B"]`, `bShortestPathCount: "2"`, and `stableExports: 2`. This deterministic demo report omits random source epochs and server-assigned UUIDs. Actual evidence retains both. Demo generations live only for the lifetime of its owned fixtures.

## Library usage

Reference `src/MembershipEvidence/MembershipEvidence.csproj` from a .NET 10 application:

```csharp
using MembershipEvidence;

await using var fixture = await SyntheticFixture.Create();
var result = await fixture.ResolveGroup(SyntheticFixture.RootDn);
foreach (var principal in result.Principals)
    Console.WriteLine($"{principal.DisplayName}: {string.Join(" -> ", principal.Path)}");

var exported = await fixture.ResolveAndExport(SyntheticFixture.RootDn);
if (exported.Publication is { } generation)
{
    byte[] immutableJson = await fixture.ReadEvidence(generation.FileName);
    Console.WriteLine($"Evidence bytes: {immutableJson.Length}");
}

var bounded = await fixture.ResolveAndExport(SyntheticFixture.RootDn, new Limits(Groups: 2));
Console.WriteLine(string.Join(", ", bounded.Errors)); // GROUP_CAP; never an export
```

Only the fixed synthetic mutations in `FixtureMutation` are exposed. For example, `await fixture.Apply(FixtureMutation.ReplaceG2WithD)` replaces G2's entire membership in one LDAP modify operation. Compare complete same-epoch observations with `MembershipDifference.Compare(before, after)`; identity comparison uses entryUUID, not display labels.

## Why these choices?

LDAP performs DN matching; the client does not lowercase or implement DN equality. Every member reference uses a base-object lookup. Returned display DNs and Unicode attributes are preserved. An exact-string cache saves requests, but deduplication uses server-assigned entryUUID. A bounded breadth-first traversal builds a graph; a separate graph analysis chooses shortest paths using ordinal fixture-identifier ordering and reports strongly connected group components.

Ordinary LDAP reads are **not snapshots**. Qualified stable export requires a cooperating writer's source epoch and equal even revision before/after traversal. The final check and immutable no-replace publication hold the same filesystem `flock` used by the writer. Every writer must cooperate. A failed batch can leave an odd revision: export then blocks until disposal and a new fixture seeded with a fresh epoch. The lab never guesses whether that batch committed.

## Boundaries and limitations

- Ceilings: 256 groups, 1,024 principals, 4,096 observed member edges, **32 total sequential LDAP requests**, and a two-second monotonic observation deadline. Limits can only be lowered. The request cap often wins before the entry caps; 256 groups are not promised within 32 lookups.
- Requests include both guard reads, cache misses and missing-reference lookups. No referral chasing, alias dereferencing, arbitrary server URLs, unescaped dynamic filters, or unbounded request fan-out.
- Missing references and any cap/error preserve known partial results, mark them incomplete, and prevent publication. Incomplete results are observations, not evidence generations.
- This implements only the documented synthetic schema and cooperative protocol, not general LDAP schema support or broad standards compliance.
- Native server allocations are not fully bounded by application entry limits. The fixture's MDB map is 16 MiB; use OS memory/CPU limits too.
- Anonymous TCP reads are acceptable only inside this synthetic lab. Local LDAPI peer credentials permit the companion writer to modify synthetic data; there is no password or end-user login feature.
- The native helper owns and reaps only its direct child. Termination finishes before reap; there is no late PID-based kill fallback. Kernel-uninterruptible processes and hostile same-UID filesystem modification are outside the guarantee.
- Publication uses flush plus same-filesystem no-replace rename. It is not a power-loss durability protocol or signed evidence format. The private fixture tree is deleted after its retained server has stopped.
